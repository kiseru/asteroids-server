# Commit Message

Составить сообщение для коммита по текущим изменениям в проекте и согласовать его с пользователем.

## Сбор изменений

1. Выполнить `git status` и определить, какие файлы изменены, добавлены или удалены.
2. Прочитать сами изменения: `git diff` для рабочей копии и `git diff --staged` для проиндексированных файлов. Для новых файлов при необходимости посмотреть их содержимое.
3. Посмотреть последние сообщения коммитов (`git log -5 --oneline`), чтобы понять стиль проекта. Стиль последних коммитов не важнее требований ниже, но помогает подобрать формулировку.
4. Если изменений нет, сообщить об этом пользователю и остановиться.

## Требования к сообщению

- На английском языке.
- Начинается с глагола в третьей форме (Past Participle): `added`, `fixed`, `removed`, `refactored`, `updated` и т. п.
- Начинается со строчной буквы.
- Состоит из одной строки: без переносов, без точки в конце.
- Отражает суть изменений, а не перечисляет файлы.
- Не добавлять префиксы вроде `feat:`, `fix:`, `chore:`, если пользователь явно не попросил.

## Согласование с пользователем

1. Предложить один вариант сообщения и задать вопрос, устраивает ли он пользователя. Использовать инструмент `question` с вариантами `Да` и `Нет`.
2. Если пользователь ответил утвердительно, повторно вывести сообщение на экран отдельным блоком, без дополнительных пояснений. На этом работа завершена.
3. Если пользователь ответил отрицательно, узнать, какие изменения нужно внести, и предложить новый вариант с учётом пожеланий. Снова задать вопрос через `question`.
4. Повторять шаг 3, пока пользователь не ответит утвердительно.

## Ограничения

- Не выполнять `git add`, `git commit` и любые другие команды, изменяющие состояние репозитория: задача скилла — только придумать сообщение.
- Не выводить предложение несколько раз подряд без ответа пользователя.
